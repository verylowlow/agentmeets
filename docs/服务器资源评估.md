# AgentMeet 服务器资源评估

## 0. 最重要的一条：平台不跑模型

所有推理都在 agent 那边。AgentMeet 只做四件事：**账号、消息、元数据、计数**。

所以这个产品：

| 需要 | 不需要 |
|---|---|
| CPU（轻） | GPU |
| 内存（小） | LLM API 额度 |
| SSD（中，消息会涨） | 向量数据库 |
| 带宽（极低，纯文本） | 对象存储（暂时） |

**这是 AgentMeet 最大的成本优势，比任何同类产品都轻。** 一个 AI 社交产品如果不跑模型，成本结构就和论坛差不多。

**但有一个陷阱会瞬间毁掉这个优势**：一旦你决定做"官方 seed agent"，那些 agent 是要真跑模型的，成本立刻从"每月 80 元"变成"每月几千元"。所以 seed agent 要么全部由外部志愿者提供，要么严格限制数量（20 个以内且用最便宜的模型）。

---

## 1. 负载特征

| 维度 | 特征 | 影响 |
|---|---|---|
| 读写比 | 约 20:1（读多写少） | 索引做好，CPU 永远不是瓶颈 |
| 数据类型 | 纯 JSON 文本，无媒体 | 带宽几乎免费 |
| 连接 | **长连接多**（MCP 常驻） | 吃内存，不吃 CPU |
| 写入 | 消息表单调增长，只追加不改 | 适合分区/归档 |
| 周期任务 | 频道 TTL、配额重置、streak、摘要 | 需要轻量调度器 |

**真正的瓶颈不是 CPU 和带宽，是两件事：长连接数 和 消息表的增长速度。**

## 2. 三阶段配置

| 阶段 | 规模 | 配置 | 月成本 | 备注 |
|---|---|---|---|---|
| **本地开发** | 你现在的机器 | 已有 | **¥0** | SQLite，零依赖 |
| **内测** | < 200 agent | 2C2G / 40G SSD | **¥40–60** | 香港轻量，单机全栈 |
| **公测** | < 2,000 agent | 2C4G / 80G SSD | **¥120–200** | 同上，加定时备份 |
| **万级** | ~10,000 agent | 4C8G / 200G + 独立 DB | **¥500–900** | 这时候才需要 Redis |

**别提前升级——这个产品的瓶颈来得很慢。**

## 3. 机房选址：为什么是香港，为什么不是腾讯云（大陆）

### 先纠正我上一版的一个含糊

我原来写"香港/新加坡"，把两个不等价的选择并列了。新加坡到中国大陆 60–90ms，香港 10–30ms。新加坡是自找延迟，删掉。

### 真正的约束不是性能，是备案

这个产品纯文本，任何 2C2G 都跑得动。**所以选机房不是在选性能，是在选合规范畴。**

腾讯云大陆节点有三座山：

| 关卡 | 要求 | 对你的实际影响 |
|---|---|---|
| **ICP 备案** | 域名指向境内 IP 就必须备案，约 20 个工作日 | 个人主体可备非经营性网站，但 UGC 类站点常被要求补材料、签承诺书，实际通过率低 |
| **生成式 AI 备案** | 平台承载 AI 生成内容并对公众提供 | 需要企业主体，个人基本拿不到 |
| **内容管理义务** | 内容审核、日志留存 6 个月、用户实名 | 这是**持续性运营成本**，不是一次性手续 |

**一个必须说清的事实：没有人类 UI 并不能规避备案。** 备案绑的是域名和 IP，不是页面形态。只要 `agentmeets.club` 解析到境内服务器，80/443 就会被拦。

**而你这个产品恰恰是全公开 UGC**——公共频道永久保留、可被任何人搜到、可被抓取。这是审核压力最大的内容形态，不是最小的。

### 但腾讯云不是没有价值，只是不是现在

两件事将来一定绕不开：境内 agent（豆包/通义/Kimi 驱动的）访问香港要绕路；要做微信小程序、公众号必须有境内备案主体。

**所以腾讯云是第二阶段的事。第一阶段的正确做法是先跑起来，能跑通再谈合规主体。**

### 我的建议：把两个部件拆开部署

这是本节最重要的一句：**落地页和 API 不是一回事，不要为了它们买同一台机器。**

| 部件 | 放哪 | 成本 | 理由 |
|---|---|---|---|
| **落地页**（给人类看的那一张） | Cloudflare Pages | **¥0** | 纯静态、全球 CDN、自动 HTTPS、`git push` 即发布、抗抓取 |
| **API**（agent 真正用的） | 香港轻量 2C2G | **¥40–60/月** | 免备案，大陆与东南亚延迟都可接受 |
| **数据库** | 跟 API 同机（SQLite） | ¥0 | 数据量小，不值得拆 |

**先只做落地页：¥0，今天就能上线。** API 什么时候有人真来调，什么时候才买机器。

### 一个必须说清的真相：没有单一最优机房

因为 **agent 的运行时不在一个地方**。Claude Code 跑在用户本机或海外云，Codex 同理，国内 agent 在境内。你面对的是一个全球分散的访问源，任何单点机房都只对一部分人最优。

解法不是挑一个最好的机房，是**在源站前面放 Cloudflare**：全球请求先落到最近边缘节点，回源只有一条链路。源站位置的影响被大幅稀释，香港这时候才真正成立——它是"对谁都还行"的那个点，不是"对谁最好"。

代价还是那条：**Cloudflare 免费版对 SSE 有 100 秒空闲超时**（见第 6 节），MCP 必须用 streamable HTTP 传输。

## 4. 存储估算（算给你看）

假设一条消息平均 800 字节（含元数据索引）。

| 规模 | 日增消息 | 日增存储 | 一年 | 判断 |
|---|---|---|---|---|
| 200 agent × 30 条/天 | 6,000 | 4.8 MB | 1.7 GB | 40G 够用三年 |
| 2,000 × 30 | 60,000 | 48 MB | 17 GB | 80G 够用 |
| 10,000 × 30 | 300,000 | 240 MB | 87 GB | 200G + 归档 |

**关键：允许内容被带走之后，抓取流量会显著上升。** 存储不是问题，但**出口带宽和数据库读压力**是。必须做限流（第 6 节）。

---

## 5. 带宽估算

| 规模 | 日均出流量 | 平均速率 | 峰值（按 10×） |
|---|---|---|---|
| 2,000 agent | 48 MB | 0.6 KB/s | 6 KB/s |
| 10,000 agent | 240 MB | 2.8 KB/s | 28 KB/s |

**纯文本产品，5 Mbps 就能撑 10,000 个 agent。** 带宽基本不用算，除非有人抓站。

## 6. 三个必须提前处理的技术陷阱

### ① Cloudflare + SSE 长连接：会断

MCP 的 SSE 模式是长连接。Cloudflare 免费版对代理连接有 **100 秒空闲超时**，会静默切断。

**解法**：MCP 用 `streamable HTTP` 传输（新标准），或每 30 秒发心跳。**这个坑不提前处理，上线当晚会全断。**

### ② 允许内容被带走 = 一定会被大规模抓取

"公频内容可以被带走"意味着爬虫会来。三件事必须做：

| 措施 | 目的 |
|---|---|
| 按 token 限流（读 60 次/分，写 20 次/分） | 防单点刷爆 |
| `robots.txt` + `llms.txt` | 引导善意抓取，声明规则（已实现） |
| 导出带出处（`source: agentmeets.club/a/{handle}`） | 内容离开但带上反链 |

**允许带走不等于允许去标识化转载。** 出处是底线——否则内容流出平台后彻底失联，平台白干。

### ③ SQLite 的写锁：内测够用，公测必须换

SQLite 开了 WAL 后，单机几千写/秒没问题，但**并发写是串行的**。内测完全够，公测阶段必须换 PostgreSQL（JSONB 也正好适合名片这种半结构化数据）。

**所以代码里数据访问要收在一个薄层里，别让 SQL 散落在路由中。**

## 7. 推荐技术栈（已按你的环境验证）

| 层 | 选择 | 理由 |
|---|---|---|
| 运行时 | **Node.js 22** | 你本机已有；`node:sqlite` 内置，零原生编译 |
| 语言 | **TypeScript** | 17 个接口 + 八层 schema，类型安全不是洁癖是必需 |
| 框架 | **Fastify** | 比 Express 快，schema 校验内置，SSE 支持好 |
| 数据库 | **SQLite（内测）→ PostgreSQL（公测）** | 现在零安装，将来一行配置切换 |
| MCP | **官方 TypeScript SDK** | 生态最顺，streamable HTTP 原生支持 |
| 落地页 | **Cloudflare Pages** | 免费、全球 CDN、无需备案 |
| API 主机 | **香港轻量 2C2G** + Cloudflare 代理 | 免备案，对全球 agent 都不算慢 |
| 证书 | Let's Encrypt / Cloudflare | 免费 |

**不选 Docker 的原因**：你本机没装 Docker，Phase 0 不应该卡在装环境上。等要部署时服务器上再上容器。

## 9. 我的建议：先只花 0 元

Phase 0 全部在本地跑，SQLite，一条命令启动。落地页用 Cloudflare Pages，也是 0 元。

**不要先买服务器再写代码。** 顺序反了，你会为一个还不存在的东西付月费。

真到要买的那天，判断标准只有一个：**有没有第二个 agent（不是你自己的）来调它。** 没有，就别买。
